# Shover-World

**A discrete grid-world environment with box pushing mechanics and an A\*-based Player AI.**

This repository implements the Shover-World project in two phases. The project starts with a custom grid environment where an agent interacts with boxes, lava, barriers, stamina, and perfect-square mechanics. The second phase extends the environment with a classical A\* search-based Player AI, heuristic evaluation, and subgoal selection.

---

## Project Overview

Shover-World is a discrete grid-world environment designed around box-pushing mechanics.

The main environment includes:

- Agent movement in four directions
- Single and chain box pushing
- Lava and box destruction
- Stamina and pushing-force mechanics
- Barriers
- Perfect-square mechanics
- Special actions such as Barrier Maker and Hellify
- Random or file-based map generation
- A Pygame-based GUI

In **Phase 2**, the project adds an intelligent Player AI based on:

- A\* search
- Explicit search-state representation
- Energy-based heuristic evaluation
- Subgoal selection
- State/environment reconstruction
- Plan extraction and replay

The AI is designed with practical search performance in mind rather than strict optimality guarantees.

## Phase 1 — Environment

Phase 1 implements the core Shover-World environment.

### Main mechanics

- Grid-based agent movement
- Box pushing
- Chain pushing
- Stamina consumption
- Initial pushing force
- Lava interaction and box destruction
- Barriers
- Border lava
- Perfect-square detection and aging
- Barrier Maker
- Hellify

### Cell Representation

- `0` → Empty
- `1..99` → Box
- `-100` → Lava
- `100` → Barrier

The environment treats every positive value below `100` as a box.

### Running Phase 1

From the `phase_1` directory:

```bash
python test.py
```

To run the Pygame interface:

```bash
python gui.py
```

To run the Phase 1 tests:

```bash
pytest phase_1/tests -v
```

## Phase 2 — Player AI

Phase 2 extends the environment with a classical search-based Player AI.

The AI represents a search state using:

```text
State =
    agent position
    agent direction
    box positions
```

### A\* Search

The Player AI uses A\* search to explore possible actions.

For each state, valid successors are generated by reconstructing an environment from the current search state and applying the available actions.

### Energy Heuristic

The heuristic considers several properties of the current state:

- Number of remaining boxes
- Remaining stamina
- Distance to lava
- Box-chain length
- Number of perfect squares
- Distance between the agent and a target box
- Distance between a target box and lava
- Current subgoal

The heuristic also includes subgoal-based shaping to guide the search toward useful intermediate states.

### Subgoals

The `SubgoalManager` selects subgoals according to the following priority:

1. `push_to_lava`
2. `use_perfect_square`
3. `approach_box`

These subgoals provide additional guidance for the heuristic during A\* search.

### Running the Player AI

From the `phase_2` directory:

```bash
python player_ai.py
```

The AI can also be used through the interactive GUI:

```bash
python gui_ai.py
```

The GUI supports both manual interaction and AI-controlled execution.

## Map Format

Maps are stored as plain-text files.

Numeric maps use values such as:

```text
0       empty
10      box
-100    lava
100     barrier
```

The environment also supports symbolic maps using:

```text
.       empty
B       box
L       lava
#       barrier
A       agent
```
